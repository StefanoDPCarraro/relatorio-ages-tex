\section[Desenvolvimento do Projeto]{Desenvolvimento do Projeto}
Nesta seção, são fornecidas informações relativas ao desenvolvimento do projeto, abrangendo a localização do código-fonte e documentação, a arquitetura e as tecnologias utilizadas, bem como os protótipos de tela desenvolvidos. Além disso, são apresentados os artefatos desenvolvidos ao longo do semestre em que o projeto foi realizado. 

\subsection{Repositório do Código Fonte do Projeto}
  Seguem os repositórios do código fonte, eles foram divididos entre front-end e
back-end, utilizando de scripts com um Linter para garantir que o código
permanecesse formatado.

Além disso foram utilizados padrões de commit, no back-end era feat/USnº/nome, já no front era feat/pagina/função.

\subsection{Banco de Dados Utilizado}
  O banco de dados escolhido foi o PostgreSQL, um banco de dados da categoria
relacional, tendo em vista a facilidade e robustez que este tipo de banco oferece, ainda
mais levando em conta que o esquema a ser implementado teria diversas entidades,
tabelas e relações.
Além disso foi usado um mapeador, chamado TypeORM para facilitar a
implementação das funções do banco de dados.

\subsection{Arquitetura Utilizada}
  O modelo de arquitetura escolhido foi o \ac{mvc}, onde o usuário interage com a
parte de view, o banco de dados interage com o model e o controller integra as duas
anteriores.

    Também faz parte da arquitetura o uso do padrão aberto de segurança \ac{jwt}, que provê mais segurança para aplicativos e sistemas, através de sistemas de autenticação e autorização, garantindo que apenas usuários autorizados acessem o site.

\subsection{Tecnologias Utilizadas}
  Na parte do front-end foi utilizado TypeScript devido à organização e robustez
que a linguagem oferece em relação ao concorrente JavaScript, como biblioteca foi
utilizado o React, para poder tirar um ótimo proveito dos ganchos que ela proporciona,
além disso a organização de código \ac{html} e TypeScript na mesma página facilita a
compreensão de iniciantes no desenvolvimento web.

  Já para estilização foi utilizado o Sass, uma extensão de \ac{css} que simplifica operações lógicas, como criação de
variáveis, aninhamento hierárquico de código, do ponto de vista técnico ele não difere
em nada do \ac{css}, já que após compilado vira \ac{css}, ainda assim facilita muito a vida de
iniciantes com sintaxes mais simples.

  Já na parte do back-end foi utilizado o framework NestJS com a linguagem
TypeScript, para a criação de uma \ac{rest} API. Além disso, como tecnologia de
mapeamento relacional foi usado o TypeORM, responsável por facilitar a
comunicação entre back-end e banco de dados.
